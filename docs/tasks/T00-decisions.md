# T00 范围与决策冻结

doc_id: T00
status: planned
depends_on: []

必读：[P01](../product/brief.md)、[P02](../product/requirements.md)、[D04](../delivery/risks.md)。所有权：`docs/delivery/decisions/`（未来创建）；需主 agent 同步范围文档，不改应用代码。

在用户授权开发后，把原始要求、默认值、明确接受的差异整理为决策记录。用户已加入 R12–R15，且指定 KernelSU Next + Shizuku Root；这些不是待审批选项。系统 DNS 在普通/高级模式分别实现。其余需区分内置编译引擎、前台 iperf 服务端、iOS 功能差异；不要重复请求已有授权或答案。

确认可用 Android 设备/网卡、目标最低系统、发布渠道以及 macOS/iOS 验证资源。记录未知项及负责获取证据的人，不靠默认假定硬件存在。T03 失败后才需要讨论网页降级，不能提前替用户批准。

产出：带日期的范围决定、设备矩阵、允许先推进的独立工作、原目标尚未满足的事项。验收：11 项原需求与四项高级扩展没有被删掉；差异有“接受/未接受/待验证”状态；验证分别落到 T01–T03 与 T14。

失败处理：某项差异未确认时，独立调查仍可推进；不得把原始目标改成较小目标后标完成。交接包含具体决定与来源，不只写“已对齐”。
