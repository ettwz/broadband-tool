# 临时网络配置与恢复

doc_id: A06 · 仅 Android 高级模式

目标是临时调试选定 USB Ethernet，而不是永久修改全机网络。配置改动可能影响使用该接口的其他应用；页面需说明。默认会话 5 分钟，可选 1–30 分钟；不提供永久保留按钮。

## 状态与执行顺序

`preview → prepared → applying → awaiting_confirmation → active → restoring → restored`；异常可进入 apply_failed / recovery_pending。每一步有 transactionId、接口身份、权限 generation 与前后快照。

1. 预览保存系统 Ethernet 配置（DHCP / 静态）、地址/路由/MTU/链路状态及本 App 将变动的条目。未知或无法恢复的字段阻止应用配置；摘要落盘后再修改。
2. 独占选定接口的修改权；停止主动任务和抓包；复核 generation。系统管理层和内核状态必须一致，不能只运行 ip 命令后假装 Android 已切到新配置。
3. 应用完成先检查地址/路由/MTU，再显示 **30 秒确认**。无公网不等于失败；局域网直连允许网关为空。用户“继续临时使用”仅延续本次有时限会话。
4. 未确认、会话到期、正常返回/切后台、用户结束时发起恢复；恢复仅撤回本 App 的变更，不覆盖用户或系统后来作出的新设置。DHCP 恢复指重新交还 DHCP 管理，不保证取回旧 IP。
5. 验证配置与可观测状态后才能显示“已恢复”。系统重新配置、USB 断开或复用接口名时，不向新设备套用旧快照；显示 recovery_pending，等待重新识别并引导恢复。

## 失权与崩溃

Shizuku 停止、撤权或 Root 模式消失后，App 可能已经没有恢复能力。**不承诺此时总能自动恢复。** 显示“恢复未完成”，冻结新的配置操作，保留脱敏恢复记录；恢复授权后重新核对接口与当前状态，再执行必要恢复。

应用进程崩溃时，由事先验证过的、有界执行生命周期尝试按期限恢复；不能仅依赖页面计时器。T14 必须验证 UserService 实际生存/清理行为，不能因使用 daemon 选项就声称可靠。若未验证崩溃后的有界恢复，配置写入功能不得放行。撤权后不能绕过 Shizuku 继续获取权限。

重启恢复以系统实际状态为准；记录尚在不等于改动仍在，必须重新读回。恢复失败提供原/现配置对照、重新连接 Shizuku 和系统网络设置指引，不用一条通用命令覆盖所有 ROM。
