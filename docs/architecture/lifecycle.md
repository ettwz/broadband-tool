# 生命周期、历史与恢复

doc_id: A04

一期普通模式只允许运行一个主动诊断任务，避免测速与探测互相干扰。网络概览可监听状态；开始测速时暂停主动 Wi-Fi 扫描并标注原因。telnet 会话和 iperf 服务端也占任务位。

高级模式增加明确例外：最多一个被动抓包会话，可陪同一个主动诊断；系统 DNS 清理也可在抓包下观察，但不得与另一 DNS 主动任务重叠。ARP 主动探测、DHCP Discover 占主动任务位；独立 DHCP 被动观察与抓包共用一个捕获资源，不创建重复抓包器。网卡配置应用/恢复独占修改阶段，先停止全部主动任务和捕获；配置 active 阶段允许诊断，恢复前再次停止。测速与抓包并行须记录资源开销提示。

每个引擎在工作线程运行。取消必须关闭任务拥有的 socket、计时器、回调和网页连接，不能仅停止 UI。建议停止响应 ≤2 秒；超时必须记录 ENGINE_FAILED，不得显示已停而继续流量。iperf3 的信号处理、全局状态和阻塞调用需在 T02 验证封装方式。

**一期基线为前台使用。** 切后台、锁屏或进程退出均停止测试/监听，保存 interrupted 摘要；返回前台不能自动开始测速或重新监听。UI 提前说明“切后台会停止”，长测试时可在前台使用屏幕常亮且结束立即释放。不把“服务端模式”包装成后台常驻服务。若以后增加后台运行，另立前台服务类型、通知、系统时限和 iOS 限制任务。

高级抓包也遵循前台限制。配置的限时恢复属于清理职责，不能因 UI 停止就忘记；App 崩溃、Shizuku 停止/撤权等条件按 [A06](network-recovery.md) 处理。权限已丢失且无法核对时显示 recovery_pending，不一律记 completed，也不悄悄切换 root 获取路径。

原生网络句柄仅在当前进程有效。应用启动清除陈旧句柄；未有终态的持久记录标 interrupted。重启后保留表单偏好和历史，不恢复活动 socket，不自动连 telnet。

本机历史默认最近 100 条 / 合计 5 MB 摘要，超限按时间删除；Wi-Fi 时间曲线只保留当前会话最近 10 分钟。原子写入、schemaVersion 和损坏文件隔离；写失败不影响当前诊断结果。删除历史不清系统网络配置。

抓包文件单独限额管理，见 F09；恢复日志不能按普通历史超额策略删除。任何尚未确认恢复的事务，保留原/现状态、接口身份与下一步动作。操作完成和恢复完成是两件事；配置页面退出不自动代表事务已结束。

telnet 输入和会话正文不进入默认历史；主机和端口可由用户保存，密码不保存。网络名称、BSSID、公网 IP 属于敏感诊断信息；分享前预览并可隐藏。公网服务会看到请求 IP，按对应页面说明提示，不增加自有云端采集。
