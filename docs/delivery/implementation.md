# 开发与验证记录

doc_id: D07 · 2026-10-27 · 当前功能版本：0.1.5

本页是面向公开仓库的摘要，不记录真实设备地址、网络名称、MAC、主机账号或本机绝对路径。逐项验证状态见 [D09 验证清单](validation.md)，安装和测试入口见 [D08](apk.md)。

## 已实现

- Android 9+ 的 arm64 / x86_64 应用，名称为 `broadband-tool`；共享 Flutter 界面，预留 iOS 接入边界。
- 网络概览、Wi-Fi 列表/信号趋势/信道图、iperf3 双角色 TCP/UDP、公网 IPv4、Ping/TCPing/Telnet/Traceroute/DNS、受约束的测速网页和本机历史。
- 信道图只缩放横轴；纵轴刻度固定，左右拖动查看局部，上下滑动滚动页面，扫描刷新保持视野。
- Traceroute 接受域名和 IPv4。域名按选定网络解析 A 记录，固定实际目标后追踪；结果和停止历史保留实际 IPv4。
- Shizuku Root 下的抓包、ARP/DHCP 和系统 DNS 缓存清理。有线临时配置具备事务实现，但写入尚未开放。

## 可复核的开发验证

| 范围 | 结果与证据边界 |
| --- | --- |
| 本地检查 | 4 项原生、23 项 Flutter、34 项 JVM 测试通过；静态检查与 5 项源码导出测试通过 |
| Android 9 / 14 | 普通协议、实际 socket、WebView 代理与停止、主要界面及异常退出恢复已测 |
| 信道图 | 40 个模拟 AP 验证缩放、拖动、刷新、边界、窄屏和大字体；不当作真实无线扫描 |
| iperf3 | 客户端/服务端、TCP/UDP、反向接收及停止互通通过 |
| Traceroute | 域名解析、探测启动和停止通过；IPv4 回环到达；当时公网示例未收到逐跳回应，未确认完整路径 |
| DNS 解析错误 | 受控响应验证 NXDOMAIN → DNS_FAILED、无 A 答案 → NO_IPV4；不修改真实网络 DNS |
| Root 抓包 | 选接口捕获、诊断并发、PCAP 结构、停止、导出与删除通过；异常退出文件标为未完整结束 |
| 系统 DNS | 两张隔离系统网络证明缓存命中、只清目标网络、其他网络缓存不变；真实 Shizuku 调用与应用缓存隔离通过 |
| 发布构建 | 双架构、签名、ZIP/ELF 16 KB 对齐和发布入口检查通过；无临时测试证书或 debug DNS 夹具 |
| 从源码构建 | 干净源码副本可重建，不依赖预编译 iperf 或 PEM 文件；复用了已安装的工具链/依赖缓存 |

硬件补充：维护者此前确认 **OnePlus 13 上 0.1.4 功能集的全部已开放功能使用正常**。这是人工真机验证反馈，独立于上述自动化记录；0.1.5 回归及未单独记录的故障注入、频段、网卡、Private DNS 组合见 [D09](validation.md)。

## 关键实现记录

iperf3 的 Android 线程取消与继承信号屏蔽问题已修复，修改位置和上游许可见 `native/third_party/manifest.json`。发布版 JNI 回调保留规则已通过实际 Ping/Trace 回归。

系统 DNS 使用完整的 AOSP 冻结 v10 AIDL 生成客户端，核对服务 descriptor、远端版本和存活状态，不猜 Binder 调用编号。两个无接口的临时网络配合回环 DNS 响应器，验证缓存命中和单网络清理；`DnsResolver.FLAG_EMPTY` 不绕过系统缓存，夹具结束时清理自己创建的对象。

有线配置的本地事务测试覆盖未确认恢复、期限、外部修改、接口身份变化、重启和失败记录。它们不替代真实网卡写入/恢复验证，故写入继续关闭。iOS 尚未完成编译和设备验证。
