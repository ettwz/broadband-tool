# 风险与范围决策

doc_id: D04 · 本页不把推荐降级当成用户已同意

| ID | 风险 / 冲突 | 当前结论与下一步 | 负责 / 门槛 |
| --- | --- | --- | --- |
| K01 | iOS 周边 Wi-Fi 扫描 | 公开通用 API 不支持；iOS 能力表保留差异；外置扫描硬件仅是另一个产品范围 | T00、T13；不得承诺双端等同 |
| K02 | 系统 DNS 清理范围 | 普通模式仍只清应用缓存；用户已加入 Shizuku Root 下的当前网络系统缓存清理，不代表清其他应用或上游缓存 | T14、T18；版本适配与受控验证 |
| K03 | WebView 严格选卡 + IPv4 | 两者必须同时证明；受控绑定/代理仅候选，失败则提出明确例外供用户选择 | T03；未过不能完成完整一期 |
| K04 | ping / traceroute 非特权权限 | ICMP 能发不等于逐跳能收；OEM 与 iOS 差异需实测 | T02、T09；保留不支持设备清单 |
| K05 | iperf3 移植与取消 | 上游未保证移动端；多 socket、全局状态、退出信号均有封装成本 | T02、T08；双角色/取消必须过 |
| K06 | USB 网卡兼容 | 系统驱动、供电和 OTG 决定是否存在网络；App 不安装驱动 | T01、T05；列出实际验证设备 |
| K07 | 第三方站点变化 | PoW、限流、跨域和网页结构会变化；无稳定 SDK 承诺 | T03、T11；本地模拟，有限手工检查 |
| K08 | “国际测速”误解 | FAST 用分布式 CDN，不能保证流量出境 | T11；界面清楚命名 |
| K09 | iOS IPv6-only 发布要求 | Android IPv4 首期不变；iOS 基础联网与诊断限制另评 | T01、T13；iOS 上架前门槛 |
| K10 | 后台服务端预期 | 本方案前台监听，切后台停止；若要求锁屏持续需要单独评估 | T00、T08；界面说明 |
| K11 | Shizuku 身份误判 | 已安装/已运行/ADB shell 不等于 Root；服务与 UserService 都要检查，能力逐项测试 | T14、T15 / V13 |
| K12 | root 仍被系统拒绝 | SELinux、capabilities、内核和驱动差异不能靠 root 图标消除 | T14–T19；不要求关闭 SELinux |
| K13 | 临时配置恢复失败 | App 崩溃、失权、拔线、接口复用都可能阻止恢复；保留恢复未完成状态与记录 | T14、T19、T20 / V17 |
| K14 | 抓包与测速相互影响 | 允许明确的被动观察并发，记录开销、丢包、截断和实际接口 | T16、T20 / V14 |

## 建议作为后续开发默认值

Flutter、Android API 29 起、arm64 首发、无账号、一个主动任务加可选被动抓包、本机历史、无蜂窝自动回退。高级环境已由用户指定为 KernelSU Next + Shizuku Root，四项功能已获规划授权，不再询问是否加入。

## 开发前确实需要明确的差异

只有改变已授权目标的事项才需要新决策：T03 若失败是否接受系统网络网页模式；原版独立 CLI 文件是否为硬要求；若指定 Root 路径不能完成某项高级功能，是否接受明确的范围例外。不能自行改用直接 su 来绕开 Shizuku 管理，也不能退回普通缓存清理后宣称完成系统清理。iOS 扫描限制仍要明确披露。

目前没有应用、设备证据或站点授权协议，不给“全部无风险可实现”的结论。规划交付可以完成，产品实现仍受这些开发门槛约束。
