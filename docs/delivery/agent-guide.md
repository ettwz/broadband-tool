# Goal / subagent 执行规则

doc_id: D02

这套文档用于用户后续授权开发后启动 Goal。**本轮仅规划，不因任务卡存在而自动开始开发。** 每个 agent 先读总索引，再只读所属任务的必读文档。任务有待验证能力时，真实失败可以完成“验证调查”，但不能完成相应产品功能。

## 分配模板

> 完成 Txx；先读 docs/INDEX.md 与对应任务卡。你只负责任务列出的目录。你不是唯一在仓库工作的 agent；不要撤销别人的改动，发现共享契约冲突先联系集成人。完成标准是任务卡列出的行为和验证证据。不得扩大范围、隐藏平台限制或伪造成功。先说明完成标准，再实现并验证。交付变更路径、运行命令、测试环境、成功/失败、证据路径和剩余问题。

主 agent 持有总 Goal、依赖状态、共享 schema、依赖清单和集成权。子任务不能改变总目标，不能因为单测通过就宣称手机功能可用。多 agent 必须在当时用户或适用规则授权的情况下启动。

## 顺序与并行

- T00 后，T01 / T02 / T03 可并行，各写自己的 spike 目录；在契约冻结前不抢写共享平台包。
- T04 独占 scaffold、依赖锁文件、schema 和代码生成；完成交接后 T05 建网络基础。
- T06 / T07 / T08 / T09 / T10 / T11 可按可用 agent 数分批并行。公共路由注册、依赖清单和权限清单由集成人串行合入。
- T12 必须在功能汇总后执行跨功能与真机验收；T13 依赖 Android 基线完成，但早期 iOS 验证不得拖到 T13 才做。
- 用户已授权规划的高级扩展先做 T14/T15，随后 T16 与 T18 可并行；T17 依赖 T16 捕获资源，T19 再依赖 T17，最后 T20 汇总，具体依赖以 TASKS 为准。T15 独占高级入口/授权/共享边界，T16–T19 只改各功能子目录；恢复事务由 T19 所有。T20 是高级联合放行，不让 T12 的普通基线证明替代它。

每个任务状态：planned / running / waiting-evidence / done / failed-investigation。done 必须有证据引用；物理设备缺失记 waiting-evidence，不能把模拟器结果升级为真机通过。Goal 是否阻塞仍遵循当时系统的阻塞审核规则，而不是看到一个 waiting 就暂停全部工作。

## 交接内容

任务 ID、依赖版本、改动文件、公共接口变化、验证命令与结果、设备/OS/网卡/网络、输出或截图路径、未验证边界、已知风险、下一任务。日志脱敏；不提交密码、telnet 原文或完整公网 IP。每个任务只检查/暂存所属路径，不覆盖用户已有文件。提交、推送、上架是分别授权的动作，不由“功能完成”自动推出。
