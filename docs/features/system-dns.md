# 系统 DNS 缓存清理

doc_id: F11 · 高级需求 R14，扩展原需求 8

普通 DNS 页继续提供“清除本应用 DNS 缓存”。高级页单独提供 **“清理当前网络的系统 DNS 缓存”**，展示网络、IPv4、系统 DNS 地址与 Shizuku Root 状态。用户主动点击后按所选 Android Network / netId 调用；不默认清所有网络，不默认附带重启 DNS 服务。

界面明确作用于 Android 系统解析器，不包含浏览器/其他应用的私有缓存、路由器或上游 DNS。可以单独选择一并清除本应用缓存，默认关闭。系统服务未提供条数时不显示“清理了 N 条”。[S03-08](../research/sources-root.md)

操作结果分为“系统已接受清理请求”“清理失败”“当前系统不支持”“权限已断开”。可提供“重新查询验证”，展示所选网络上的查询，但普通网站一次查询变快/变慢不能证明清理成功。功能支持标记只能来自系统调用与受控测试证据，不能用绕过缓存查询冒充清缓存。

0.1.3 使用 AOSP 冻结的 DNS resolver v10 AIDL 完整契约生成客户端，核对服务 descriptor、接口版本（至少 v10）和存活状态；Android 9 或接口不兼容时禁用。采用编译器生成的调用，不手写 Binder transaction 编号，不使用旧式 ndc 清理命令。系统平台代理可能裁掉未使用的方法，因此不再依赖反射找到其清缓存方法。[S03-10](../research/sources-root.md)

原生层根据已校验的选定 Network / generation 生成 netId，覆盖调用参数里的 netId，避免把清理指向另一网络。Android 14 已通过两张隔离系统网络的缓存命中/清理/互不影响验证，并验证了真实 Shizuku Root 调用和应用私有缓存隔离；OnePlus 13 的日常使用已获维护者人工验证通过反馈。Private DNS 组合及其他 ROM 仍需专项记录，见 [D09](../delivery/validation.md)。

验收：受控 DNS 服务准备有 TTL 的答案；确认系统缓存命中时上游无新请求；更新受控答案，执行系统清理，再用**不绕过系统缓存**的同网络查询验证上游重新收到请求。应用层缓存应隔离，另验证其他网络未被清理、Private DNS 路径、权限拒绝和服务接口变化。清理成功不等于当前 DNS 服务器本身正确。
