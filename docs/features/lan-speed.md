# 局域网测速

doc_id: F02 · 原需求 2 · 引擎：iperf3

客户端与服务端是同等的一期交付项。设备之间必须有路由且对端运行兼容 iperf3；不兼容 iperf2。显示“测本机与指定设备之间的有效吞吐”，不把 Wi-Fi 链路协商速度等同结果。[S02-07、08](../research/sources-services.md)

| 参数 | 默认 | 校验 / 行为 |
| --- | --- | --- |
| 角色 | 客户端 | 客户端 / 服务端 |
| 目标 | 用户填写 IPv4 或域名 | 域名仅解析 A；服务端不填目标 |
| 端口 | 5201 | 客户端 1–65535；服务端 1024–65535 |
| 协议 | TCP | TCP / UDP |
| 方向 | 本机发送 | 客户端反向接收可选，方向始终用本机视角标注 |
| 时间 | 10 秒 | 5–120 秒 |
| 并发流 | 1 | 1–8；UDP 初版固定 1 |
| UDP 目标速率 | 10 Mbps | 1–1000 Mbps，提示这是目标值不是保证值 |
| 报告间隔 | 1 秒 | 一期固定 |

实时显示 Mbps、已传字节、经过时间；结束显示发送/接收侧吞吐，TCP 重传在引擎提供时显示，UDP 丢包/抖动与方向关联。单位：Mbps=10⁶ bit/s，MB=10⁶ bytes；不使用 MB/s 冒充 Mbps。

服务端只监听选定 IPv4，显示监听地址、端口、对端和状态。默认等待一场测试，完成后停止；空闲 5 分钟自动停止。启动前确认选定接口可入站；端口被占用显示 PORT_IN_USE。不能监听 0.0.0.0 后宣称只提供给所选网卡。

典型实验：实验 PC 运行 `iperf3 -s -4`，手机作为客户端；手机启动服务端后 PC 运行 `iperf3 -c <手机IPv4> -4 -t 10`。补测 `-R`、UDP、对端中断、服务端占用、拔线和取消。验证源地址、协议互通、接收侧统计与 PC 输出的差异；允许测量环境波动，不凭固定“达到千兆”数字放行。服务端前台生命周期遵循 [A04](../architecture/lifecycle.md)。
