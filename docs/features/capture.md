# 按网卡抓包

doc_id: F09 · 高级需求 R12

用户选 Wi-Fi / USB Ethernet 等可见接口，选择“IPv4 + ARP”“DNS”“DHCP”“指定 IPv4 / 端口”等预设，开始后显示时间、包数、流量、丢包计数、协议摘要和文件大小。原始接口与本机流量为范围，不承诺监听全家设备或解密 HTTPS。Wi-Fi 使用正常联网模式，不切 monitor。[R06](../research/root-access.md)

默认 60 秒、20 MB，达到任一上限停止；可选 10–300 秒、5–100 MB。默认每包截取 256 字节，完整载荷需明确选择；界面说明截取会影响深度解析。IPv4 过滤同时保留 ARP，避免第一期范围把链路排障所需报文过滤掉。保留实际链路类型；不伪造 Ethernet 头。

抓包可以与一个普通诊断任务同时运行，用于解释 ping / DNS / iperf3；同一时间最多一个抓包会话。测速时显示抓包可能影响结果，记录是否同时抓包。网卡临时配置不能与抓包并行；切换网卡、失权、切后台时关闭捕获，不自动追随系统默认网络。

DHCP 被动观察复用同一捕获资源。共享时后端可合并采集范围，但保存文件仍只按用户选定过滤条件写入；不能为观察 DHCP 悄悄扩大用户导出内容。不支持共享的后端明确返回 BUSY。

会话结束区分停止完成、达到上限、权限丢失和文件不完整；先关闭并完成文件写入，再提供 pcap/pcapng 导出。文件不进入 5 MB 历史摘要配额，单独受 200 MB 本机总额控制；超额先提示清理。导出只发生于用户操作，不上传。抓包摘要关联 taskId，但不可把无法归属的包强行标给某应用。

验收：已知 ARP、DNS、TCP 与 DHCP 报文、Wi-Fi/有线分别选卡、与 VPN 共存、无 IPv4 仍可抓 DHCP、停止后无捕获进程、文件可被 Wireshark 读取；补测空间不足、权限撤回、并发诊断、截断包和丢包。丢包为零只在实际计数支持时显示，未知不是零。
