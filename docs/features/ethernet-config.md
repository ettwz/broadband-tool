# USB 有线网络临时配置

doc_id: F12 · 高级需求 R15，扩展原需求 4 / 11

仅对用户选定、系统已识别的 USB Ethernet 接口提供写入；Wi-Fi、VPN、蜂窝仍只读。首屏显示当前接口、DHCP/静态模式、IPv4/前缀、网关、MTU，以及保存的原配置摘要。未验证系统适配或恢复能力时只读。

| 表单 | 默认与规则 |
| --- | --- |
| 模式 | DHCP / 临时静态 IPv4；切换也通过配置事务 |
| IPv4 / 前缀 | 用户填写，拒绝重复、非法、广播/组播和与本机其他配置冲突的输入 |
| 网关 | 可空，支持无上网需求的直连；不在可达子网时说明错误 |
| 路由 | 可选一条明确目标 IPv4 网段及网关；默认不修改全机默认路由 |
| MTU | 默认保留；按接口支持范围校验，不任意突破驱动限制 |
| 会话期限 | 5 分钟，可选 1–30 分钟 |

“预览变更”展示原值 → 临时值和影响接口；“应用并检查”之后有 30 秒确认窗口，“继续临时使用”只保留到本次会话结束。所有运行页面持续显示临时配置与剩余时间，提供“结束并恢复”。

支持手工“重新连接此网卡 / 重试 DHCP”，须说明会短暂断开连接，并通过同一快照/恢复流程。不能以退出页面替代恢复，也不能假定 KernelSU Next 或 Shizuku 自带回滚。具体异常规则见 [A06](../architecture/network-recovery.md)。

验收：无 DHCP 时静态直连设备、空网关、所选路由/MTU 生效、系统与内核状态一致、30 秒未确认恢复、会话到期、正常退出；再测 App 崩溃、Shizuku 停止/撤权、拔插、更换网卡、接口名复用、系统更新配置和恢复失败。恢复 DHCP 可得到新地址，只要管理方式和相关状态正确，不要求旧 IP 原样回归。真实能力与恢复证据未过时不开放写入。
