# ARP / DHCP 排障

doc_id: F10 · 高级需求 R13

选择物理接口后进入“ARP 检查 / DHCP 观察”页签；不要求接口已经拥有 IPv4，不要求能上网。输入和输出绑定 InterfaceRef，网络回调不足时使用已验证的高级接口枚举。

## ARP 检查

目标为一个 IPv4，可选“检查网关”“检查地址占用”。默认 3 次、1 秒间隔、总时限 5 秒；输出响应 IP/MAC、耗时与样本。地址占用检查使用重复地址检测语义；有回应显示“地址已被使用”，无回应只显示“未观察到占用”，不能保证空闲。相同 IP 出现多个不同 MAC 时提示“疑似地址冲突”，保留报文证据；不自动改对方 ARP 缓存。

## DHCP 观察与探测

默认被动观察当前接口 30 秒（最多 120 秒），展示 Discover → Offer → Request → ACK / NAK 时间线，只匹配本设备相关事务。显示服务器标识、所提议地址、掩码、网关、DNS、租期与响应时间。缺失步骤标“未观察到”，不补造流程。

“发送发现请求”为独立动作：提示会产生额外请求，服务器可能短暂预留所提议地址；最多 3 次带独立事务 ID 的 Discover，匹配当前接口/本设备身份。不发送 Request/Release，不完成租约确认、不伪装其他设备。主动探测受单主动任务限制。若需要重试系统 DHCP，通过 F12 的配置事务处理，不在诊断按钮内偷偷重配。

观察多个服务器回应只提示“检测到多个 DHCP 服务器”，不直接断言恶意或配置错误。第一期不增加全网扫描、ARP 欺骗或 DHCP 服务端。

验收：网关回应/不回应、目标已占用、相同 IP 多 MAC；正常/缺失步骤/DHCP NAK、两服务器、旧事务响应、不同接口混杂、没有本机 IPv4、取消和失权。受控服务证明没有因发现探测完成额外租约确认或释放已有地址，不将 Offer 阶段的临时预留当成已获租约。依据 [S03-07](../research/sources-root.md)。
