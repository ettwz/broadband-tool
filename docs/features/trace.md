# 路由追踪

doc_id: F05 · 原需求 7

首屏只有一个“目标 IPv4 或域名”输入框和“开始”按钮。接受严格点分十进制 IPv4 或有效域名（含国际化域名）；不接受 URL、IPv6、端口后缀、shell 字符或附加参数，拒绝未指定、广播及组播目标。高级选项一期不暴露。

域名通过所选网络解析 A 记录，选择第一个可用单播 IPv4，并在整次追踪中固定该地址；解析与探测使用同一网络。结果显示输入域名和实际追踪 IPv4，停止后的历史也保留目标信息。解析失败或没有可用 IPv4 时明确报错，不启动追踪，不改测 IPv6。

建议默认：TTL 从 1 开始，最多 30 跳；每跳 3 次探测；每次最多 1 秒；整体 100 秒上限；到达目标、不可继续错误、用户停止或网络改变时结束。默认不反查 PTR，避免 DNS 干扰和额外输入。

输出每跳序号、收到响应的 IPv4 和三次 RTT，缺失为 `*`。同一跳出现多个响应 IP 时分别保留，不强行合成一条确定路径。ICMP type/code 在详情展示；结果区分“到达”“达到跳数上限”“部分路径”“被拒绝”“取消”。中间设备不回复不表示其后网络不可达。

Android 候选是 UDP 探测、IP_TTL 与 IP_RECVERR 错误队列。必须解析原始目标/端口等信息匹配探测，不能把无关 ICMP 回复算进结果。非特权权限和 OEM 支持由 T02 决定；iOS 用独立适配验证，不假定有 Linux 错误队列。[R03](../research/tools.md)

验收覆盖域名解析/IPv4 地址输入、实际目标展示、解析失败/无 A 记录、停止和非法 URL/IPv6/地址。完整路径验收使用至少两跳的受控实验网络，已知第一跳与末跳；再让中间节点不回复，验证仍继续；拒绝目标、最大跳数、双网卡出口。真实公网 traceroute 只能作为补充，因为路由器可以过滤或限速响应。

若设备沙箱不能取得逐跳响应，返回 UNSUPPORTED 并记录机型、系统与失败证据，阻止宣称此设备满足完整一期。不得把 ping、tcping 或远端服务器代测当作本手机路由追踪的替代完成。
